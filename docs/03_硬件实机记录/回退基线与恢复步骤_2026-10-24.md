# 回退基线与恢复步骤

> 2026-10-24 18:30 | 场景：另一个窗口要基于当前代码接 agent_stack，必须保证能退回今天这个"能跑、能演示"的状态。
> 结论：**四层备份，四个恢复入口。按"坏到什么程度"选，不要一上来就整片恢复。**

---

## 0. 一句话

| 坏成什么样 | 用哪一层 | 耗时 |
| --- | --- | --- |
| 代码改乱了，想推倒重来 | git 标签 | 10 秒 |
| 新固件能烧进去但功能坏了 | 应用分区 bin | 20 秒 |
| 分区表 / NVS / 字库被动过，板子起不来或连不上网 | 整片 16 MB 镜像 | 6 分钟 |
| 文档、后端、数据被改了 | 工作区 tar.gz | 1 分钟 |

| L1 源码 | `D:/Agent_link` 全部代码，标签 `pre-agent-stack-2026-10-24`（提交 `8b7c14a`） | git 仓库 | `git show pre-agent-stack-2026-10-24` |

## 2. L1 源码回退（最常用）

```bash
cd D:/Agent_link
git stash            # 先把对面正在改的东西收起来，别丢
git checkout pre-agent-stack-2026-10-24
```

只想看差异不想切：

```bash
git diff pre-agent-stack-2026-10-24 -- firmware/apps/waveshare-epaper-397-wifi/
```

**注意**：`git checkout` 只动源码，不动已经烧进板子的东西。切完必须重编重烧才算真回退。

## 3. L2 应用分区回退（20 秒，最安全的"能跑就行"）

```bash

"D:/ESP_IDF/espressif/python_env/idf5.5_py3.11_env/Scripts/python.exe" -m esptool \
  --chip esp32s3 -p COM6 -b 460800 --before default_reset --after hard_reset \
  write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x10000 "D:/WorkBuddy_Projects/2026上海AI硬件黑客松/firmware/backup_portrait_2026-10-24/agent_link_portrait_1620352.bin"
```

- **不动** bootloader、分区表、字库、NVS → WiFi 与设备绑定全保留
- 实测 17 秒写完，重启后约 4 秒出首页

## 4. L3 整片回退（6 分钟，最后的底牌）

```bash
"D:/ESP_IDF/espressif/python_env/idf5.5_py3.11_env/Scripts/python.exe" -m esptool \
  --chip esp32s3 -p COM6 -b 921600 --before default_reset --after hard_reset \
  write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x0 "D:/WorkBuddy_Projects/2026上海AI硬件黑客松/firmware/backup_fullflash_2026-10-24/board_full_16mb.bin"
```

**这是覆盖式的**：板子当前的一切——包括别的分支烧进去的分区表、被擦的 NVS、被换掉的字库——全部替换成 18:26 那一刻的状态。

什么时候必须用它：
- `agent_stack` 改了分区表（最可能发生的一种）
- 板子起不来、串口刷 `invalid header` / `partition table` 相关错误
- 重新配网后仍连不上，怀疑 NVS 坏了
- 字库分区被覆盖（屏上英文能显示、中文全空白）


## 6. 怎么确认备份没坏

不用重烧，读回来比对即可：

```bash
# 只读回应用分区，跟备份比
python -m esptool --chip esp32s3 -p COM6 -b 921600 read_flash 0x10000 0x18B980 /tmp/app_now.bin
python -c "import hashlib;a=open('/tmp/app_now.bin','rb').read();print(hashlib.sha256(a).hexdigest())"
# 期望 7f33a337ce9e5bf0aaf0ec5a6931916a60d29489abe2add1a4ba86e3b67ed9ff
```

整片备份的自检（已经做过一次，结果见第 1 节）：

```python
d = open('board_full_16mb.bin','rb').read()
assert len(d) == 16*1024*1024
assert d[0:4].hex() == 'e903024f'            # bootloader 镜像头
assert d[0x8000:0x8004].hex() == 'aa500102'  # 分区表魔数
assert d[0x412000:0x412008] == b'AGLKTTF1'   # 字库头
assert d[0x10000:0x10000+1620352] == open('agent_link_portrait_1620352.bin','rb').read()
```

## 7. 恢复后必须做的自检（5 分钟）

| 步骤 | 期望 |
| --- | --- |
| 上电看首页 | 「就医通 / 请说一声你好 / 中键说话　长按菜单　音量xx%」 |
| 长按中键 | 「菜单」+ 6 项，字号明显比页脚大（40 px） |
| 选「院内科室位置」 | 「中山医院科室」10 条一页，40 px |
| 选「去医院」 | 大字路线卡，5 行，标题「去复旦大学附属中山医院」 |
| 按 BOOT 回主页 | 只留"请说一声你好"，**不能有上一轮对话的文字** |
| 说一句"你好" | 屏幕出现 AI 回复；按 BOOT 后回复消失 |

**最后两条是今天刚修的两个 bug**，如果回退后发现它们又出现了，说明退回的是更早的版本（`ccfa05e` 横屏版或更早），不是 `8b7c14a`。

## 8. 接 agent_stack 时最容易破坏的四样东西

提前告诉对面的窗口，这四样坏了一样要上 L3：

| 东西 | 在哪 | 坏了的表现 |
| --- | --- | --- |
| 分区表 | 0x8000 | 板子反复重启，串口刷 `partition` 相关错误 |
| 字库分区 `anim_pack` | 0x412000，2.2 MB `AGLKTTF1` | 英文数字正常、中文全空白 |
| NVS `ws397_wifi` | 0x9000 | 每次开机都要重新配网，或设备绑定丢失 |
| ota_data | 0xe000 | 启动槽指到空分区，看起来像"烧不进去" |

另外两件事跟备份无关，但会让演示当场挂掉：

1. **PC 在热点上是 DHCP，IP 会变**。IP 变了就要改 `route_card.h` 第 26 行并重烧 app（备用地址在 29–31 行）。
2. **后端 `route_server.py` 是另一个窗口的工作面**。回退 L4 时不要整目录覆盖。

## 9. 备份之外的两条提醒

- **L1 的标签在本地，没推到远端。** `git remote` 指向 GitHub 的 Deotaland/Agent_link，但没人 push 过这个标签。要更保险就 `git push origin pre-agent-stack-2026-10-24`——**注意仓库是公开的，里面有比赛代码**，推之前先问一句。
- **L3 里含设备密钥**（NVS 的 `auth_key`）。这份 16 MB 不要外发、不要进 git、不要贴到公开仓库。
