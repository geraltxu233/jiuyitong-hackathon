## 二、三条演示路径（按键序列）

**A 语音导诊**
```
中键（开始通话）→ 说话 → 等回复 → BOOT（挂断）
```
屏幕依次显示 `Connecting voice...` → `Call active / listening`。

**B 院外路线**
```
长按中键 1 秒 → 中键（第 1 项「去医院」）→ 等约 3 秒 → 出卡 → BOOT
```
**C 院内科室**
```
长按中键 1 秒 → 下 → 中键（第 2 项「院内科室位置」）→ 中键（心内科）→ 出卡 → BOOT → BOOT
```
BOOT 是逐级返回：详情 → 列表 → 主页。

## 三、换屏要等 2–2.5 秒，这是面板物理限制

- 局部刷新实测 2042–2057 ms，全刷 2444–2450 ms（见任务清单 D2）。
- **按下后等屏幕刷完再按下一个键**；刷新期间的按键会被丢弃（防误触连跳，不是卡死）。
- **BOOT 不受这个限制**，任何时候按都能退回主页。

## 四、故障处置

| 现象 | 先查 | 处置 |
| --- | --- | --- |
| 屏幕全黑 / PC 上找不到 COM6 | USB 线、板子电源 | 换线换口重插；**COM6 稳定消失＝板子断电或线掉了**，不是软件问题 |
| 屏上「网络不好，请再试」 | PC 后端还在跑吗 | 重启 `python backend/route_server.py --port 8000`；页面能按中键重试 |
| 屏上「路线查询失败 / 响应格式错误」 | 后端日志有没有 `[warn]` | 看是哪一行超宽；改文案或接受固件截断 |
| 一直停在「正在查路线」 | PC 还在不在 `192.168.82.0/24` | `ipconfig` 里**看不到 192.168.82.x ＝ PC 掉出热点了**，先连回 MEIZU 热点；再看 IP 是否仍是 `192.168.82.100`，变了要改 `route_card.h` 第 23 行重烧（约 60 秒） |
| 按了没反应 | 是不是刚按过键 | 等 3 秒；不行按 BOOT；再不行断电重开 |
| 屏幕自己重启 | 有没有误碰 **PWR** | PWR 只管电源，按下即断电重启。演示时手别放那儿 |
| 麦克风没反应 | 是否已在通话态 | 按 BOOT 退回主页，重新中键起通话 |
