## 一、一句话说清这是什么

一台给不会用智能手机的老人用的**导诊卡套**：按一下键说话，AI 问清症状、判断轻重、给出"最好"和"最近"两个医院选择；选完长按中键，墨水屏出一张公交路线卡（大字、5 行、一屏看完）；到了医院，屏幕出科室所在的楼栋楼层。

**它不做什么**（明确划掉，避免被问倒）：不做诊断、不挂号、不查实时公交、不做定位、不保留跨通话记录。

## 三、用户视角的完整流程

### 3.1 原始设计（用户提的七步）

```
开机初始化（AI 自我介绍）
  ↓
AI 与人对话：人说症状 → 判断急症 / 非急症
  ├─ 急症：人说位置 → AI 给"就近 + 最好"两个方案 → 人确定
  └─ 非急症：AI 引导录入基础信息 → 人说症状、位置 → AI 给两个方案 → 人确定
  ↓
院外导航（1 页，步行少、换乘少；按键确认是否到达）
  ↓
院内科室显示
  ↓
按键结束
```

### 3.2 裁决后的流程（现行）

```
按中键起通话
  ↓
「您好，我是就医通，您哪儿不舒服？」
  ↓
听症状 → 判断轻重
  ├─ 红：只念「这个不能等，马上打一二零」→ 流程中断
  ├─ 黄：让家属立刻送急诊，别坐公交 → 问有没有人陪
  └─ 绿：补四项基础信息 → 判断科室 → 给两个方案 → 老人选
  ↓
老人长按中键 → 菜单选「去医院」→ 屏幕出 5 行路线卡
  ↓
到了医院 → 菜单选「院内科室位置」→ 屏幕出科室大字卡
  ↓
BOOT 结束
```

### 3.3 五处和原始设计不一样，及原因

| 改动 | 原因 |
| --- | --- |
| 急症由二分类改三档 | 二分类没有"疑似"出口，会逼模型在信息不全时选一边；漏判代价是命 |
| 急症分支删掉"两个方案" | 急诊讲就近不讲排名，心梗不会送 8 公里外的专科强院；疼得说不出话的人不该做选择题 |
| 非急症先听症状、后录基础信息 | 老人带着症状来；四项只影响挂哪个号，不影响挂哪个科 |
| 院内科室不走 AI 口述 | 同一份 JSON 已编译进固件上屏；口述是第三份冗余，且与屏幕不一致时无解 |
| 两个方案的医院信息来自 JSON，不靠模型记忆 | 平台无检索能力，模型只会编，且编得像真的 |

## 四、技术架构三层与硬约束

### 4.1 固件层

| 项 | 值 |
| --- | --- |
| 板子 | ESP32-S3 + 微雪 3.97 寸墨水屏（物理 800×480） |
| 逻辑分辨率 | **竖屏 480×800**（`Pixel()` 恒转置 `px=y, py=479-x`，设备顺时针转 90° 看） |
| 字号 | 双实例：28px（标题×2=56、页脚、来源行）+ **40px（正文）** |
| 正文容量 | 40px 一行 11 个汉字，正文区 11 行（横屏时是 5 行/页、要翻页） |
| 按键 | 中键=通话/确认，长按中键=菜单，上下=音量/选择，BOOT=结束/返回 |
| 菜单六项 | 去医院、院内科室位置、样例路线卡、选择已有会话、新建会话、重置激活 |
| 应用分区 | 0x10000，bin 1.54MB / 2MB，剩 467KB |
| 构建 | `D:/ESP_IDF/espressif/python_env/idf5.5_py3.11_env/Scripts/python.exe D:/ESP_IDF/idfrun.py build` |
| 烧录 | 只写 `0x10000`，不动 bootloader/分区表/字库，NVS 里的 WiFi 与 auth_key 保留 |

### 4.2 后端层

| 项 | 值 |
| --- | --- |
| 进程 | `backend/route_server.py`，0.0.0.0:8000，双击 `start_backend.bat` 启动 |
| 接口 | `GET /api/transit?from=demo&to=hospital` |
| 契约 | `{code, title, lines[], source}`，错误时给 `message` |
| 起点 | 西岸国际会展中心行人主入口 `31.162751,121.462919`（**预设常量，不做定位**） |
| 终点 | 中山医院东院区 `31.197019,121.456540`，POI `6577562127214739761` |
| 腾讯接口 | `/ws/direction/v1/transit/`，policy=RECOMMEND，双策略合并后自排序 |
| 排序 | 少走路（≤200 米优先分档）> 少换乘 > 总耗时 |
| 输出 | 压到 5 行，丢"开往方向"、换乘步行提示、上车点；换乘站名与首末步行必须保留 |
| 超时 | 腾讯侧 3 秒硬超时（板端一次 GET 最多等 8 秒），超时立刻给缓存 |

### 4.3 平台层

| 项 | 值 |
| --- | --- |
| 平台 | Deotaland，智能体「就医通」，类型 `desktop_voice_bot` |
| 通道 | LLM=`agent_stack/live-chat`，实时语音=`agent_stack/live-real` |
| 能改 | 名称、简介、**个性化补充人设（上限 4096 字节）** |
| 改不了 | 知识库、文件、工具箱、MCP、自定义 HTTP |
| 硬限制 | 人设 4096 字节；跨通话无记忆；实时通道不读人设（新对话才读） |

## 六、踩过的坑

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 板子连不上后端 | 固件里根本没有 HTTP 客户端 | 补写 `route_card.cc`（HttpGet + cJSON 解析） |
| 2 | PC 上能打开、板子打不开 | 防火墙规则只在"公用"profile，MEIZU 热点被判"专用" | 手工加 `profile=any` 规则 |
| 3 | 上午通了下午不通 | PC 是 DHCP，IP 从 192.168.82.100 变到 192.168.219.100 | 固件加候选地址列表 |
| 4 | 路线 9 行、要翻 2 页 | 腾讯原始 steps 太细 | 后端合并"乘 X 路坐 N 站"，丢"开往方向" |
| 5 | 推荐方案要步行 1.86km | LEAST_TRANSFER 只优化换乘次数 | 改 RECOMMEND + 自排序（少走路优先） |
| 6 | 屏上显示"地铁10号" | 行宽超了被截断 | 去"地铁"前缀 |
| 7 | "浦西滨江1路"被截 | 一行塞不下"在哪上车+坐几站" | 拆成两行 |
| 8 | 首页连续刷 3 次屏 | 状态变化逐次触发重绘 | 调试信息改成条件显示（有内容才画） |
| 9 | 科室卡按 BOOT 直接回主页 | 刷屏 2.45 秒内按键被丢弃，人必然连按 | 纯页面导航加 `epaper::Current()` 门控 |
| 10 | 编译报 format-truncation | `Screen.detail` 只有 192 字节，说明文字 249 字节 | 扩到 320 字节 |
| 11 | UI 任务栈吃紧 | Screen 结构涨到约 2KB，又叠两个 4KB 缓冲 | 全改 `static` 局部（单实例无并发） |
| 12 | 40px 下 10 个汉字被截成 9 个 | `TextClipped` 给每个字都预留 48px 省略号宽度 | 最后一个字不再预留 |
| 13 | AI 自称"TiDB 助手" | 实时通道（live-real）不读人设 | 新建对话才生效，且跨通话无记忆 → 流程压成单次通话内闭环 |
| 14 | 人设粘贴被拒 | 网关限 4096 字节，控制台却说 10 万字符 | 压到 3948 字节；三条入口都绕不过 |

## 八、当前状态

### 8.1 真机验证过的（可以拿去演示）

- 实时语音对话：起通话、上行音频、下行 TTS，180 秒抓包核过
- 公交路线卡：西岸会展中心 → 中山医院东院区，5 行、步行 585 米、换乘 1 次、50 分钟，与腾讯原始数据逐条对账 10 项全过
- 科室大字卡：9 条列表 → 大字页，BOOT 逐级返回，H13 已验收
- 首页：标题「就医通」、正文「请说一声你好」、页脚音量
- 竖屏 40px：已烧录，**上屏效果还没有人眼确认**

### 8.2 没做完的

| # | 事 | 影响 | 谁做 |
| --- | --- | --- | --- |
| 1 | 起点固定还是可变（未拍板） | 决定"最近"能否靠人设算；可变就必须改成上屏按键选 | 用户 |
| 2 | 选起点页代码 | 起点若可变才需要 | 固件侧 |
| 3 | 5 个科室没有"最好"数据 | 呼吸/神内/内分泌/肾内/普外给不出排名，只能用降级话术 | 数据侧 |

| 7 | 后端 696px 口径没随竖屏更新 | 行超宽告警会漏报 | 软件侧 |

### 8.3 已知限制（对外要说清楚）

1. **跨通话无记忆**：第二通电话要从头说一遍，流程必须单次通话内闭环
2. **坐车只支持中山医院**：选其他三家只能打车
3. **不做定位**：起点是预设常量
4. **不做诊断**：只分轻重、只指科室，红旗一律转 120
5. **人设余量只剩 148 字节**：任何增补都要先量字节
6. **TLS 不可用**：板端 32KB 连续内存不够，全程明文 HTTP，只能在可信局域网内跑

### 8.4 现场必须同时成立的三个条件

1. PC 和板子在同一热点（MEIZU，192.168.82.0/24）
2. `start_backend.bat` 在跑，端口 8000 占住
3. 固件里写的 IP 和 PC 当前 IP 一致（不一致就改 `D:/Agent_link/firmware/apps/waveshare-epaper-397-wifi/route_card.h` 第 22 行重烧）
