# 服务器部署与平台激活交接（2026-10-24）

> 负责：有 `47.116.139.125` SSH 权限的队友。范围只到部署与验收，**不要自行激活 Connector**。
> 当前平台：TiDB Link，组织 `WTCC-Group-2`。
> Connector：`CareCardTransit` / `conn_76d4e812-3f05-42d2-8408-1d7f80c8c015`，inactive / version 1。
> 服务包：`handoff_route_card_v1.1.0.zip`，不含账号、密码、Org Key、connectorKey、腾讯 Key 或数据库。

## 一、为什么必须先部署

平台已注册 Connector，但公网仍是 1.0.0。1.1.0 增加：

- 官方 `params._meta["tidb-link/context"]` 中的 `sessionId/callId`；
- `/mcp` 全部请求的 Bearer 鉴权；
- 正式模式不再接受 `arguments` 中伪造的会话身份；
- `raw_log` 敏感头脱敏。

激活会触发平台 discovery。**必须先完成本交接全部验收，再由主窗口单独确认激活。**

## 二、密钥交接边界

- 压缩包可以直接转发。
- `connectorKey` 在主要负责人的本机私密文件中，必须通过团队安全密钥渠道单独交付；不要发微信、群聊、文档或命令行。
- 最稳妥的方式是让队友在主要负责人的电脑上完成部署，避免传输 connectorKey。
- 服务器已有 `/opt/route-card/.env` 和 `data/`，部署不得删除或覆盖其中的腾讯 Key 与数据库。

## 三、部署步骤

### 1. 上传并解压

把 `handoff_route_card_v1.1.0.zip` 上传到服务器 `/tmp`，然后：

```bash
cd /tmp
unzip handoff_route_card_v1.1.0.zip -d /tmp/route-card-v1.1.0
```

### 2. 备份并覆盖程序文件

```bash
sudo cp -a /opt/route-card /opt/route-card.backup-$(date +%Y%m%d-%H%M%S)
sudo cp -a /tmp/route-card-v1.1.0/handoff_route_card/. /opt/route-card/
```

压缩包不含 `.env` 和数据库，不会用空配置覆盖线上配置。

### 3. 写入 connectorKey

```bash
sudo nano /opt/route-card/.env
```

在文件末尾新增一行，等号后粘贴安全渠道取得的实际值：

```bash
CONNECTOR_KEY=实际connectorKey
```

保存后收紧权限：

```bash
sudo chmod 600 /opt/route-card/.env
```

### 4. 重启并检查版本

```bash
sudo systemctl restart route-card
curl --noproxy '*' -sS --max-time 15 http://127.0.0.1:8010/health
```

期望看到：`"version":"1.1.0"` 和 `"key":"loaded"`。

### 5. 验证未授权请求被拒绝

```bash
curl --noproxy '*' -sS -o /dev/null -w '%{http_code}\n' --max-time 15 \
  -X POST http://127.0.0.1:8010/mcp \
  -H 'Content-Type: application/json' -d '{}'
```

期望：`401`。

### 6. 跑公网完整验收

```bash
cd /opt/route-card/test
set -a
source /opt/route-card/.env
set +a
bash verify.sh https://keleshiyizhimao.com
```

通过线：**8 通过 / 0 失败**。其中包括真实腾讯查询、官方 Call Context 写卡、Bearer 401、五行卡片与同 callId 幂等。

## 四、完成后回传

只回传以下非敏感结果：

1. `/health` 中的版本和 Key 加载状态；
2. 未授权 `/mcp` 的 HTTP 状态；
3. `verify.sh` 最后一行通过数；
4. 若失败，只贴脱敏错误，不贴 `.env`、Authorization 或完整 raw_log。

主要负责人收到 8/8 后，再执行：激活 Connector → Console 挂载 Default Agent → 新建 Session → 文本/语音/板端联调。

## 五、回滚

仅当 1.1.0 验收失败且影响现有演示时执行：

```bash
BACKUP=$(sudo ls -dt /opt/route-card.backup-* | head -n 1)
sudo systemctl stop route-card
sudo cp -a "$BACKUP"/. /opt/route-card/
sudo systemctl start route-card
curl --noproxy '*' -sS --max-time 15 http://127.0.0.1:8010/health
```

回滚后平台 Connector 仍保持 inactive，不影响现有手工 `/mcp` 兜底演示。
