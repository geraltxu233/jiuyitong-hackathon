### 修正：无明确科室时不得列出科室楼层（10:20）

**实机复测暴露（10:14 那轮）**：病人“后背烧得慌”，Agent 判定可能消化也可能心脏，原话是“建议您去一楼服务台，让工作人员帮您看看具体挂哪个科更合适”，**没有推荐科室**；老人自己选了肿瘤医院，Agent 又说“这个科我没有排名”。板子长按后文本匹配不到科名，退回全院列表，老人点第 1 项看到“肿瘤科 1 号楼 6F 第六诊区”。

**判定：是交互设计错误，不是数据错误。**

| 层次 | 问题 |
| --- | --- |
| 交互 | 语音让老人去服务台，屏幕却给科室楼层，等于绕过医嘱替他分诊 |
| 机制 | 上一版“从语音文本认科室”只在文本恰好含科名时成立，未兑现“直达推荐科室” |
| 数据表达 | 肿瘤医院“肿瘤科”同一页写“1 号楼 6F 第六诊区”和“肿瘤内科门诊在 2 号楼 2 楼”，原始 JSON 即如此（不同亚专科不同楼），不是生成错误，但老人容易看懵 |

**修正**：

| 改动 | 行为 |
| --- | --- |
| 新增 `Page::kDeptHint` | 无推荐科室时显示“这次没定科室 / 请到一楼服务台问 / 自己猜科室容易走错” |
| 中键仍可用 | 提示页中键进科室列表查位置，保留老人自己知道科名的场景 |
| 否定信号表 | 文本含“服务台 / 分不清 / 都有点关系 / 都可能 / 没有排名”即判为无推荐，防止把鉴别诊断当成推荐 |
| 直达条件 | 只有真正命中科名且无否定信号才直接打开详情 |

**固件**：1,628,656 字节，SHA-256 `343521e8029d64b09c6dac1ec84b8939793886868e54c7583a620bba9d14922f`，归档 `firmware/agent_link_v3_1_r8_dept_hint_2026-10-25.bin`，仅烧 `0x10000`，`Hash of data verified`。

**仍存在的机制缺陷**：自然语言文本当协议不可靠，两个失效模式（无推荐时误命中、有推荐时措辞不符）无法穷举。正解是 `query_transit` 增加 `department` 参数并在 `normalize_card` 返回，由“模型确认推荐”而不是“事后猜文本”驱动；但公网服务端连 `card_id` / `built_at` 都未部署，必须先打通部署通道。
