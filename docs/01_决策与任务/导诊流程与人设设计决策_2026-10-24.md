## 一、一句话结论

**AI 只做"听懂"和"说清"，不做"算"和"记"。**

医院、排名、距离、楼层这些是事实，必须来自 JSON；谁最近、谁最好是算术和查表，不是语言问题；模型只负责把老人说的话映射到科室，再把结论说成人话。原设计把这三件事全塞进提示词，所以错。

## 二、三个问题的回答

### （1）AI 怎么判断急症

原来的流程写的是「判断是急症或者不是急症」，**这个二分类本身是错的**。

- 二分类没有"疑似"出口，会逼模型在信息不全时选一边。
- 两类错误代价不对称：漏判是命，误判是多花一趟车钱。
- 老人不用医学术语：「胸口像压了块石头，一身汗」是典型心梗表达，但里面没有"胸痛"两个字。纯关键词必漏，纯模型在端侧小模型上不稳。

裁决：**三档 + 红旗原话锚点 + 缺省偏重**。

| 档 | 判据 | 动作 |
| --- | --- | --- |
| 红 | 命中红旗清单（胸痛伴大汗/放射、嘴歪说话不清半身无力、晕倒抽风、喘不上气、大量出血呕血黑便、腹部板状硬、摔后不能动或畸形、炸裂样头痛伴吐） | 只念一句「马上打一二零」，**流程中断**，不问年龄性别、不给方案 |
| 黄 | 未命中红旗但含危险词（疼晕喘麻抽出血）+ 今天开始或越来越重 + 高危基础病 | 就近去医院急诊，别坐公交，问有没有人陪 |
| 绿 | 其余 | 走常规科室流程 |

两条边界：不做病名判断（只说"不能等"，不说"你这是心梗"）；**追问最多 1 轮**，缺信息按更重那档处理。

红旗清单的写法要点：写老人怎么说，不写医学诊断名。写「压得慌、像压了块石头」，不写「压榨样疼痛」。

### （2）就近和最好，是 AI 搜索提供的吗

**不是，也不可能。** 平台物理上不给检索：

- Deotaland 的 Agent 没有 tools / MCP / knowledge 入口（OpenAPI 60 条路径里相关 schema 一个都没有）
- `execute` 只能跑平台预置通道（LLM / VoiceChat / TTS / ASR / VLM），不是任意 HTTP
- 所以 Agent 说「中山医院心血管全国第二」只有两种来源：训练时固化的记忆（会过时、会编楼层），或人设里喂的文本

AI 编楼层的能力很强，而且编得非常像真的。所以「最好」和「最近」必须来自 JSON，且要分清谁算：

| 判断 | 本质 | 该谁做 |
| --- | --- | --- |
| 就近 | 算术（比距离） | 后端或预计算常量（确定性） |
| 最好 | 查表（比排名） | 后端或预计算常量（要能改、能查出处） |
| 症状 → 科室 | 语义归一化 | **模型**（唯一该模型做的） |
| 把结论说成人话 | 表达 | **模型** |

### （3）为什么在提示词里预设医院名单是错的

错的位置和"预设"本身无关，**错在预设了结论句**。

| 风险 | 事实 |
| --- | --- |
| 数据分叉 | JSON 里中山消化记"全国第 9"，提示词写"消化科也很强"；JSON 里仁济消化在 9 号楼 2F，提示词说"浦东七公里多"。同一事实两份表述，改一处必漏一处 |
| 起点焊死 | "离这儿不到四公里"里的"这儿"是西岸会展中心坐标。起点一换，整段全错，**而且不报错**，只会开口说错话 |
| 不可审计 | "心血管全国第二"在提示词里是无出处字符串，评委一问数据哪来的就答不上；JSON 里至少有 `strengths` 字段可挂榜单 |

正确的做法不是"不预设"，而是**预设事实表，不预设结论句**：

- 原来写的是「心内科最好的就是中山医院，离这儿也最近」——不可改、不可查、起点一变就错
- 现在写的是「由近到远：中山、肿瘤医院、市六、仁济」+「中山心内全国 2、消化 9」——模型现场比大小，结论必然和 JSON 一致，改数据自动生效，能贴出处

**但这条路有个硬前提：距离必须是常量，所以起点必须固定。** 人设是静态的，改不了。

- 起点固定为预置点 → 现在这条路成立
- 起点要自由 → 只能改成：AI 只判科室，板端回传后端，后端算两家，**上屏让老人按键选**，不走语音

## 三、流程逐段裁决

| 段 | 原设计 | 问题 | 裁决 |
| --- | --- | --- | --- |
| 开机自我介绍 | AI 自我介绍 | 长介绍对老人是噪音，且每通电话都重来（平台无跨通话记忆） | 只说一句「您好，我是就医通，您哪儿不舒服」 |
| 急症判断 | 二分类 | 见第二章（1） | 改三档 |
| 急症分支 | 人说位置，AI 给就近 + 最好两个方案让老人选 | **急诊讲就近不讲排名**，心梗不会送 8 公里外的专科强院；且疼得说不出话的人不该做选择题 | 删掉两个方案，只给「最近的有急诊的三甲 + 一二零」，流程中断 |
| 非急症：录基础信息 | 先录四项再说症状 | 老人是带着症状来的；且四项只影响挂哪个号，不影响挂哪个科 | 改成先听症状，再补四项 |
| 非急症：两个方案 | AI 说最好和最近 | 数据必须来自 JSON，不能靠模型记忆 | 人设里放排序 + 排名，规则比大小 |
| 院外导航 | 1 页，步行少换乘少，按键确认到达 | 已实现（后端 `/api/transit`，5 行一屏） | 保持。「按键确认到达」是否要留，本轮未讨论 |
| 院内科室 | AI 口述楼栋楼层诊室 | `tools/gen_dept_table.py` 已把同一份 JSON 编译进固件上屏（H13 已验收），口述是第三份冗余；且口述与屏幕不一致时无解 | 删掉口述，改成「我给您打到屏幕上，照着走」 |
| 按键结束 | 按键结束 | 无异议 | 保持 |

## 四、人设里放什么、不放什么

| 层 | 内容 | 持有者 | 进人设 |
| --- | --- | --- | --- |
| 语义层 | 症状→科室映射、红旗识别、追问策略 | 模型 | 进（给锚点，不给诊断） |
| 事实层 | 医院名单、排名、远近排序 | JSON → 压缩进人设 | 进（受 4096 字节约束） |
| 事实层（大件） | 科室楼栋、楼层、诊室、走法、门诊时间 | JSON → `dept_table.cc` → 屏幕 | **不进**（只走屏幕） |
| 决策层 | 谁最近、谁最好、两方案怎么说 | 规则（比大小） | 进规则，不写结论 |
| 表达层 | 口语化、句长、符号禁用、复述 | 模型 | 进 |

## 五、4096 字节这个坑

第一版 v2（6741 字节）粘贴被拒，暴露出平台三层口径不一致：

| 位置 | 声称上限 | 实际 |
| --- | --- | --- |
| 控制台输入框 | 10 万字符 | 提交时被下游拦 |
| OpenAPI `prompt` 字段 | 「不超过10万字」 | 声明值不等于可接受值 |
| **Agent Stack (TiDB Link) 网关** | **单条 4096 字节** | 真硬限制 |

三条入口都绕不过：控制台直接被拦；API 直写可能被网关截断（后 40% 规则静默丢失，比报错更危险）；agent_link 固件从不读这个字段。

已压缩到 **3948 字节**（CRLF 最坏 4002）。压缩手法：

- 删掉所有解释性说理句
- 删掉医院门牌号（只留"在徐汇""在浦东"判远近）
- 四个科的完整话术改成「规则 + 一行示例」
- 合并重复出现的「不要猜」「不要编」

**没有砍**：急症红旗 8 类、科室映射 8 科、四家医院排序、四个科的最好/最近答案、坐车与院内的降级路径。

余量只剩 **148 字节**（约 49 个汉字）。后续增补必须先量字节。

## 七、被推翻的判断（留档）

| 原判断 | 推翻原因 |
| --- | --- |
| 提示词里写死「心内科最好中山、离这儿最近」 | 与 JSON 分叉；起点一变全错；排名断言无出处 |
| 急症二分类 | 无"疑似"出口，漏判代价是命 |
| 急症分支给"最好/最近"两个方案 | 急诊只讲就近；痛苦中的老人不该做选择题 |
| 提示词第六步口述楼栋楼层 | 与 `dept_table.cc` 上屏数据重复，是同一份数据的第三份副本 |
| 平台「10 万字符」额度可用 | 上游网关 4096 字节；Deotaland 声明的额度一律不可信 |
| 非急症流程先采四项基础信息 | 老人带着症状来；四项不影响选科室 |
