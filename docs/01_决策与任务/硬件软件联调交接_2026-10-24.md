### 2.1 会话路线卡接口

```http
GET /api/route-card?session_id=<platform-session-id>
Accept: application/json
```

成功响应：

```json
{
  "code": 0,
  "title": "去中山医院东院区",
  "lines": ["步行330米到车站", "乘浦西滨江1路坐3站", "到瑞宁路龙腾大道换乘", "乘徐汇滨江环线坐4站", "下车步行250米到院"],
  "source": "腾讯地图 50分 换乘1次 10:32"
}
```

失败响应：

```json
{"code": 3, "message": "还没有查到本次对话的路线"}
```

实现要求：

- `session_id` 必须在服务端映射到已认证设备/会话，不能接受模型或设备任意指定 `device_id`、URL 或地图坐标。
- 没有路线、查询中、过期会话、无权限、腾讯超时必须返回非 0 和适合屏幕显示的一句 `message`。
- `title`、每个 `lines` 项、`source` 均为 UTF-8；路线正文每行按 696 px 预算控制，最多 12 行，优先压到 5 行。
- 返回体控制在 2048 字节以内；不要返回腾讯原始路线 JSON。
- 公网接口必须 HTTPS；当前固件先按现有 ESP-IDF HTTPS 能力做实机内存验证，未验证前不要宣称板端可稳定访问公网 TLS。
- 接口响应不要使用长连接或分块传输；板端按一次 GET 读取并在收到 HTTP 200 后解析。

### 2.2 Connector 工具

工具名建议：`query_transit`

输入：

```json
{
  "city": "上海",
  "origin_text": "西岸国际会展中心西门",
  "destination_text": "复旦大学附属中山医院东院区",
  "travel_mode": "transit"
}
```

要求：

- 先把起点和终点解析为后端认可的 POI/坐标，再调用腾讯公交规划；模型不得自行编坐标。
- 结果同时返回给 Agent 口述，并写入与 `sessionId` 绑定的最新路线卡。
- 用 Call Context 的 `sessionId` 定位路线卡，`callId` 做幂等键，避免同一次工具重试生成多份卡。
- 地点不完整时先追问，不调用腾讯；无路线时返回结构化错误和人话原因。
- 工具日志必须能核对最终收到的 `city/origin_text/destination_text/travel_mode`，便于硬件窗口对账。

本机自测 7 项全过（真实腾讯数据，非固定响应）：

| 契约要求 | 实测 |
| --- | --- |
| 直返 200，不跳转 | 是（`Connection: close` + `Content-Length`） |
| 返回体 ≤2048 字节 | 251 字节 |
| 目标 5 行 | 5 行（9 行输入自动压到 5 行） |
| 每行 ≤696 px | 最大 504 px |
| 只回 `{code,title,lines,source}` | 是，调试字段不进板端响应 |
| 无会话不伪造 | `{"code":3,"message":"还没有查到路线"}` |
| `callId` 幂等 | 重放命中缓存，`card_id` 不变，不重查腾讯 |

**两处与契约原文不同，需硬件窗口知晓：**

1. **硬上限取 9 行，不是 12 行。** `RouteCard::kMaxLines=12`，但 `epaper_wifi.cc` 的 `kRouteRowsPerPage=9`（11 个物理行槽留 2 个给折行）。12 行要翻页，老人不会按。服务端按 9 行封顶。
2. **板端只能用 apex，不能用 `feileme.` 子域，也不能用 IP。** `feileme.` 整站 301 到 apex，板端 `disable_auto_redirect=true` 会直接失败；证书 CN 是子域，用 IP 会主机名不匹配。

**尚未验证、不要当成已通过：** 平台自己的真实调用。手工 `POST /mcp` 已实测成功，但平台自己的调用尚未发生——`raw_log` 里目前只有 `verify.sh` 自测流量与一次来源不明的 `ping`。需要用平台控制台真说一句话，再回读 `/api/admin/raw` 核对实际请求。
