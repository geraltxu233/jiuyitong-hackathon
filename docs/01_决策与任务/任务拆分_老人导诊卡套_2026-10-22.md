# 老人导诊卡套 —— 任务拆分（1 硬件 + 1 软件，两天两夜）

> 版本：2026-10-22 修正版（吸纳用户四点澄清）
>
> **修正点**：
> 1. 方言只做输入（ASR 侧可选），输出一律普通话
> 2. 震动马达不做，适老输出收敛为双通道：墨水屏大字 + 语音播报
> 3. 院内导航不做 BLE 信标，改为爬取目标医院资讯 → 科室信息墨水屏展示
> 4. 无 GPS 定位方案定为：WiFi 扫描 → 腾讯位置服务"网络定位"API

---

## 一、产品形态与架构裁决

| 事项 | 结论 |
|------|------|
| 功能本体 | 微雪 ESP32-S3-ePaper-3.97 开发板（S3R8 + BLE5 + 800×480 墨水屏 + ES8311 音频 + QMI8658 IMU + TG28 锂电管理） |
| 联网方式 | WiFi 直连（院内/赛场 WiFi）；院外环节用手机热点供网（仅借管道，非产品依赖） |
| 是否依赖手机 App | **不依赖**。ASR/LLM/地图 API 全部由板子直连云端，高光时刻全在硬件本体 |
| 产品终态（PPT 叙事） | 卡套形态（85.6×54mm，≤5mm 厚）+ 4G Cat.1 模组（Air780E ~¥30）彻底脱网脱手机；demo 用厚砖跑功能 + 3D 打印 1:1 空壳讲形态 |

## 二、五步流程 × 双人任务拆分

| 环节 | 硬件工程师（ESP32-S3 固件侧） | 软件工程师（云端/数据/API 侧） |
|------|------------------------------|--------------------------------|
| **1 导诊**（声音录入→语义识别→科室判断→展示） | ES8311 录音采集（I2S 驱动）、按键触发录音、WiFi HTTPS 上传音频、接收结果 → 墨水屏大字渲染科室名 + 语音播报调度 | 云端中转服务：音频 → ASR（讯飞/百度，可选方言模型）→ LLM 症状→科室判断 → 结构化 JSON 返回；自建科室-症状知识库；提示词调优 |
| **2 挂号（伪）** | "挂号成功 + 诊室号"墨水屏展示页 | 预置 3 个科室假号源 JSON + 挂号状态机 + 模拟接口 |
| **3 院外导航（公共交通）** | **WiFi 扫描（不连 AP）→ 腾讯网络定位 API 取经纬度**；公交方案静态展示页（墨水屏整屏刷新） | 腾讯地图公交规划 API 调用；路线精简为 3 行老人可读指令（乘几路、几站、下车怎么走） |
| **4 院内信息展示**（替代原 BLE 导航） | 科室信息大字页：科室名 + 楼栋/楼层 + 提示语 + 语音播报 | **爬取 1 家目标医院官网/公众号的科室分布、楼层索引、门诊时间**；整理科室→楼栋/楼层/房间号映射表 JSON |
| **5 适老输出** | 双通道调度：墨水屏大字（静态整屏刷新、断电保持，不做动画）+ ES8311 播放普通话 TTS 音频 | 云端 TTS 生成普通话语音包（或实时 TTS 接口）；播报文案模板 |

## 三、降级方案（每条链路都有保底）

| 风险点 | 触发条件 | 降级方案 |
|--------|----------|----------|
| 环节 1 ASR/LLM 端到端 | 响应 >5 秒或识别率不可用 | 按键选症状大类（墨水屏菜单），保住演示链路 |
| 环节 3 WiFi 定位 | 场地 WiFi 稀疏、API 不返回坐标 | 手动选起点（预置 2-3 个起点如"我家""社区医院"），按键确认后展示公交方案 |
| 环节 4 爬取 | 目标医院网页反爬/无公开楼层信息 | 手工整理该院科室表（演示只需 1 家医院、10 个以内科室） |

---

## 四、Day1 上午 Go/No-Go（2 小时红线，并行验证）

1. **环节 1 端到端**：说话 → 几秒后屏幕大字弹出科室 + 语音播报。失败 → 启用按键菜单降级。
2. **WiFi 定位**：在场地环境跑一次腾讯网络定位 API，确认能返回坐标。失败 → 启用手动起点降级。

## 五、两天排期

| 时段 | 硬件工程师 | 软件工程师 |
|------|-----------|-----------|
| Day1 上午 | ES8311 录音点亮 + WiFi HTTPS 上传打通；**Go/No-Go 两项并行验证** | 云中转服务骨架（ASR+LLM 链路）；腾讯地图/定位 Key 申请 |
| Day1 下午 | 墨水屏页面框架（导诊结果页/挂号页/公交页/科室页 4 个模板） | 科室知识库 + 假号源 JSON + 公交路线精简逻辑 |
| Day1 晚 | 音频播报链路（TTS 音频播放调度） | 爬医院资讯 → 科室楼层映射表 |
| Day2 全天 | 全流程固件串联 + 稳定性测试 | 联调 + 文案调优 + 演示脚本 |
| Day2 晚 | 联合彩排：评委说症状 → 大屏弹科室 → 挂号 → 公交方案 → 院内科室位置，全程不碰手机 | 同左 |

**演示高潮设计**：重心放在环节 1 的语音交互（老人说方言/普通话症状 → 数秒后大字+语音给出科室），环节 4 信息闭环收尾。原 BLE 震动带路方案已砍，不再作为演示点。
