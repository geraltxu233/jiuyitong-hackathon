## 3. 最重要的发现：旧 API 有原生「音频 Turn」

从 `bed43b9` 的 `openapi.yaml`（1.37 MB，200 paths / 258 ops）挖出：

```yaml
POST /api/sessions/{id}/turns/audio
  security: UserApiKey | Agent9Session(浏览器 Cookie)
  headers:
    x-agent9-project-id: <projectId>   # 必填
  body: multipart/form-data
    file: 音频文件  # 支持 mp3, mp4, mpeg, mpga, m4a, wav, webm
  201: application/x-ndjson  # 每行一个 TurnStreamEvent，空行是心跳
  429: llm_spend_limit_exhausted
  501: audio_transcription_disabled  # 因为 ASR_OPENAI_API_KEY 没配
```

**这几乎就是你们 `INTERFACE I1` 的原样**——按住说话、松手上传一段音频、等一个结构化结论。

对照一下两条路的设备端工作量：

| 项 | 旧 API 音频 Turn | 新 API Realtime WS（L2 方案） |
| --- | --- | --- |
| 传输 | 一次 HTTPS POST（multipart） | 长连 TLS WebSocket |
| 编码 | WAV 裸 PCM16 16k 即可 | 上行 PCM16 + 下行 Opus 解码 |
| 鉴权 | 后端拿 User Key 代理，设备只发音频到自家后端 | 后端换 60 秒一次性 token，设备直连平台 |
| 流控 | 无（一次性响应） | 需 `output_flow_control_v1` 防爆缓冲 |
| 中断/重连 | 无 | 需处理 `playback.stopped`、`resume_after_event_id` |
| 设备端新增失败点 | 1 个（HTTP 超时） | 6 个（TLS/WS/帧头/Opus/流控/重连） |
| 估时 | **半天到一天** | 两天且成功率 <40% |

**如果赛事跑的是旧 API，L2 那套东西完全不需要做。** 这是目前最大的方案杠杆。

### 必须提前确认的一个硬前提

`501` 的含义是：**服务端没配 `ASR_OPENAI_API_KEY` 时，音频 Turn 直接不可用。** 这不是代码能绕的。赛前必须问一句"音频 Turn 的生产环境 ASR 配好了吗"。没配的话，语音这条路当场归零，只剩文本。

## 4. 旧 API 还有一颗糖：MCP Server 是一等公民

旧契约里 MCP 是直接用 API 管的，不需要 Console 手动挂：

```
POST /api/mcp/servers                  # 注册
POST /api/mcp/servers/{id}/activate     # 激活
POST /api/mcp/servers/{id}/credential/rotate
POST /api/mcp/servers/{id}/deactivate
```

对比新 API 的 Connector：注册能走 API，但**挂到模板只能 Console 手动点**（`content.tools` 提交一律 400），且官方从未端到端验证过。

**未确认的一点：** 旧契约 1.37 MB 里我没搜到 `mcpServerIds` / `mcpServers` 这类挂在 Agent 配置上的字段，所以"注册后怎么绑到 Agent"仍然待查——可能在 `/api/console/custom-tools/{id}/mount`（Cookie 域），也可能在 Console 界面。如果最终还是得点 Console，那新旧两代在这一点上没差。

## 5. 分叉点：必须先判定赛事部署的是哪一代

我这边探不通——DNS 能解析（`ventured-agent-stack.pingcap.cn → 152.136.129.195`），但沙箱出口代理对该域名返回 `502 CONNECT`，WebFetch 也失败。**你在本机跑下面这条就能定论：**

```bash
B=https://ventured-agent-stack.pingcap.cn
curl -s -o /dev/null -w '%{http_code}\n' "$B/api/v1/org"            # 新 API
curl -s -o /dev/null -w '%{http_code}\n' "$B/api/console/projects"  # 旧 API
```

判读：

| `/api/v1/org` | `/api/console/projects` | 结论 |
| --- | --- | --- |
| 401 | 404 | 新 API，走 TiDB Link 那套（L2 风险照旧） |
| 404 | 401 | 旧 API，**走音频 Turn，砍掉 Realtime** |
| 401 | 401 | 两代共存，优先旧 API（更简单），并向主办方确认哪套是"官方推荐" |

不带密钥只会拿到 401/404，这是完全只读的探测，没有副作用。

## 6. 决策树（拿到上面结果后照此走）

```
探测结果？
├─ 旧 API 可用
│   ├─ ASR 已配 → 主链路：录音(WAV 16k) → 自家后端 → POST turns/audio → NDJSON → 屏+TTS
│   │            这条就是 L1 的最优形态，板子只多一个 HTTPS multipart 上传
│   └─ ASR 未配 → 退回文本 Turn（终端输入 / 屏上菜单选症状），语音只做本地预录 TTS
└─ 只有新 API
    ├─ L1：文本 Turn（Session events + SSE），板子仍发音频到自家后端做 ASR
    └─ L2：Realtime WS（才需要 Opus/流控/60s token 那一整套）
```
