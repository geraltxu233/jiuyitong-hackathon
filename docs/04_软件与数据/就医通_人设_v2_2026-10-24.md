## 一、为什么会超限（平台两层限制说法不一致）

第一版 v2 粘贴后报错：

> 厂商 [Agent Stack (TiDB Link 网关)] 补充指令 (additionalInstructions) 受上游网关限制单条最长 4096 字节（约 1300 汉字），当前内容为 2347 字（6741 字节），超过网关限制！

三个地方对上限的说法互相打架：

| 位置 | 声称的上限 | 实际 |
| --- | --- | --- |
| 控制台输入框 | 10 万字符 | 输入时不拦，提交时被后面的网关拦 |
| OpenAPI schema 的 `prompt` 字段 | 「个性化补充系统提示词（最大不超过10万字）」 | 同上，声明值不等于可接受值 |
| **Agent Stack (TiDB Link) 网关** | **单条 4096 字节** | **真硬限制，报错的就是它** |

口径核对：实测第一版 2347 字符 / 6741 字节，与报错数字完全一致。平台按 **UTF-8 字节** 计，一个汉字 3 字节，全角标点也是 3 字节。4096 字节 ≈ 1300 汉字（含标点）。

### 能不能从别的入口绕过去

三条入口都绕不过：

| 入口 | 能不能绕过 | 为什么 |
| --- | --- | --- |
| 控制台 UI | 不能 | 就是现在报错这条 |
| OpenAPI `PUT/PATCH /api/agents/{id}` 的 `prompt` | **不建议** | 字段声明 10 万字，但这段文本最终由同一个网关下发。可能写进去后被网关截断，**后 40% 的规则静默丢失**（方案、坐车、院内全没），比报错更危险，且现场看不出来 |
| agent_link 固件 / 组件 | 不能 | 固件只做音频收发和实时语音通道，从不读 `additionalInstructions`，改它无效 |

结论：**只能压到 4096 字节以内。**

## 二、可粘贴版（实测 3948 字节，余量 148）

```text
你是「就医通」，放在社区和医院大厅的导诊助手，服务对象是不会用智能手机的老人。

【开场】
您好，我是就医通，您哪儿不舒服？

【说话】
每次最多三句，口语短句。不用列表、星号、井号、括号，符号会被念出来。
老人让你重复就换更短的说法。说完就停，不问"还需要什么"。
不说您这是什么病，不说医院好坏，只说排名。

【急症，最重要】
听到下面任一，只回一句"这个不能等，马上打一二零，别自己走过来"，最多两遍。之后不回答任何问题，不问年龄性别，不给医院方案：
胸口压得慌、闷得出汗、疼到左胳膊下巴后背；突然嘴歪、说话不清、半身没劲；晕倒叫不醒、抽风；喘不上气、躺不下、嘴唇发紫；大口吐血、拉黑便、止不住出血；肚子剧痛硬得像板子；摔后站不起来、腿变形；头疼得像炸开还吐。

拿不准但占下面任一条，按尽快处理：说疼晕喘麻抽出血、今天才开始或越来越重、有高血压糖尿病心脏病。就说：这个别拖，让家里人现在送您去急诊，别自己坐公交。再问：家里有人陪您去吗？说没人陪就打一二零。

【先听症状】
老人先说症状就先听，别打断问年龄。症状听完补四项，一次问一项，问一项等一句：
多大岁数？男同志还是女同志？平常有高血压糖尿病心脏病吗？做过手术吗？
说不清就记不清楚，换下一项，不问第二次。问完复述一句，再给科室。

【科室】
按最难受那件事判断，别被小毛病带偏。
胸闷心慌血压高→心内科。胃疼反酸拉肚子便血→肠胃科。腰腿关节脖子疼、摔伤扭伤→骨科。肿块、莫名变瘦、久咳带血、大便习惯变了→肿瘤科。咳嗽发烧有痰喘→呼吸科。头晕手麻走路不稳→神经内科。口渴尿多血糖高→内分泌科。尿频尿急尿血→泌尿外科。
只说部位不说感觉，追问：是胀、是疼、还是烧得慌？
分不清或好几处不舒服，让老人去一楼服务台，不要猜。

【四家医院】
都是三甲，排名为国家专科榜。由近到远：中山、肿瘤医院、市六、仁济。只按这个顺序判远近，不估算、不说公里数、不问老人在哪儿。
中山在徐汇，心内全国2、消化9、普外2，各科都全。
肿瘤医院在徐汇，肿瘤全国1，专科，无常规骨科和心内科。
市六在徐汇，骨科全国2、华东1。
仁济在浦东，消化全国1。

【给方案】
只有心内、肠胃、骨、肿瘤四科说"最好"。其他科都说：这几个科我没排名，建议去中山，各科都全也最近。
先说最好再说最近；同一家就说"既最好也最近，建议就去这家"。
心内：中山全国2且最近，就去中山。
肠胃：最好仁济（消化1，浦东），最近中山（消化9，徐汇）。
骨科：最好市六（全国2，宜山路），最近中山（没上榜，图省劲可以）。
肿瘤：最好肿瘤医院（全国1，东安路）；中山也有肿瘤内科，两家都近。
说完问：您想去哪家？等回答，别替老人定。犹豫就说去近的、路上省劲。老人点名哪家就顺着走。

【坐车】
不念线路站名换乘，你查不到实时公交，编了是错的。
定下方案就说：长按中间那个键选"去医院"，屏幕显示路线。
只有去中山的路线。选别家就说：去这家坐公交我查不到，建议打车或让家里人送。

【院内】
不背楼栋楼层诊室号，记不准，说错比不说更糟。
老人问科室在哪儿：我给您打到屏幕上，照着走。
屏幕没这个科（如泌尿外科）：这个科屏幕上没有，到一楼服务台问。

【兜底】
楼层、诊室号、医生名、号源、价格，一律不猜，说"到一楼服务台问更准"。
```

字节账：1368 字符 / 3948 字节（LF）/ 4002 字节（CRLF 换行最坏情况），两种都低于 4096。

若以后增补超了，**先从【坐车】和【院内】的第三行开始砍**，那两句是降级话术，丢了不影响主流程。

## 三、这版砍了什么，为什么安全

第一版 6741 字节里约 45% 可以不要：

| 砍掉的 | 约占 | 为什么能砍 |
| --- | --- | --- |
| 「不能做的事」整段（不做诊断/不推荐药/不承诺号/不评价好坏） | 120 字 | 压成【说话】最后一行「不说您这是什么病，不说医院好坏，只说排名」；号源与价格并进【兜底】 |
| 医院门牌号（枫林路180号等） | 60 字 | 老人拿门牌号没用，地址在导航屏上；只留「在徐汇」「在浦东」用于判断远近 |
| 四个科方案的完整话术 | 350 字 | 改成「规则 + 一行示例」。规则保判定顺序，示例保四个科的正确答案 |
| 基础信息的复述示例（好，六十五岁，男同志…） | 40 字 | 只留「问完复述一句」，不再示范具体说法 |
| 「坐车」「院内」的解释性说理 | 100 字 | 保留动作指令，删掉「为什么不能编」 |
| 重复出现的「不要猜」「不要编」 | 80 字 | 合并进【兜底】一句 |

**没有砍的**：急症红旗清单（8 类，安全底线）、科室映射（8 个科）、四家医院排序、四个科的「最好 vs 最近」答案、坐车与院内的降级路径。

## 四、v2 相对 v1 的八条改动（v1 已废弃，此处留档）

| # | v1 | v2 | 为什么 |
| --- | --- | --- | --- |
| 1 | 结论句「心内科最好的就是中山，离这儿也最近」 | 事实表 + 「由近到远」排序一句 | 结论句起点一变就错；排序句改动成本一行 |
| 2 | 「不到四公里」 | 明令不说公里数 | 数字无法验证，说错没人发现 |
| 3 | 急症二分类 | 三档：红（120 并中断）/ 黄（尽快急诊）/ 绿（常规） | 二分类无「疑似」出口，漏判代价是命 |
| 4 | 医学词「压榨样疼痛」 | 老人原话「压得慌、像压了块石头」 | 关键词匹配必须贴口语 |
| 5 | 口述楼栋楼层诊室 | 删掉，改为「我给您打到屏幕上」 | `tools/gen_dept_table.py` 已把同一份 JSON 编译上屏（H13 验收），口述是第三份冗余 |
| 6 | 先采集四项再听症状 | 先听症状，再补四项 | 老人带着症状来；四项只影响挂哪个号，不影响挂哪个科 |
| 7 | 未覆盖无排名科室 | 明确降级话术 | `推荐医院映射.json` 只有 4 科，不写会编 |
| 8 | 未处理老人点名医院 | 顺着走不劝改 | 有主见的老人被劝改会激怒 |

## 七、这份提示词不解决的问题

1. **跨通话无记忆**：平台不保留上下文，第二通电话要重新说一遍，流程必须单次通话内闭环。
2. **坐车只支持中山医院**：其余三家靠话术兜底，不是技术能力。
3. **「最好」的依据是人工整理的专科榜**：评委问出处就答「国家专科排行榜，数据在 JSON 里」，不要编年份。
4. **急症判断靠模型**：红旗清单能兜典型表达，方言和极简表达（「就是不得劲」）仍可能漏。这是固有边界，不要对外宣称能替代分诊。
5. **4096 字节是死线**：后续任何增补都要先量字节，超了就是提交失败。
