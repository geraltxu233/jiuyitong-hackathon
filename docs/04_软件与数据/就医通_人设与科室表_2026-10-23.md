# 就医通：控制台能力盘点与人设草案

> 2026-10-23 | 依据：控制台三张截图 + Agent_link 固件源码核对
> 智能体：就医通（desktop_voice_bot）｜设备：gx_esp32s3（SN 51d1bc41…，MAC 44:B1:76:B7:19:00）

---

## 一、先修正我上一轮的一个判断

截图里 `LLM = agent_stack / live-chat`、`REALTIME_VOICE = agent_stack / live-real`。

这说明 **Agent Stack 不是"另一个平台"，而是 Deotaland 背后的能力通道**。我上一轮说"要用那三个能力只能切平台"，过于绝对了。准确的说法是：

> Agent Stack 的通道**已经在用了**，只是控制台没有暴露 Skill、文件、工具这些配置面。

两者关系更像"同一个后端，控制台是精简入口"。所以要拿 Skill/文件，不是换平台，而是**要更高权限的入口**（平台 API 或另一套 Console）。

## 二、你实际能改的东西

| 能改 | 在哪 | 对项目的价值 |
| --- | --- | --- |
| 智能体名称 | 编辑页 | 低 |
| **智能体简介** | 编辑页 | 中——可能进系统提示词 |
| **个性化补充人设（10 万字符）** | 编辑页 | **高——这是本项目的真正着力点** |

| --- | --- |
| 知识库 / 文件上传 | 科室表只能写进人设 |

## 三、需求一的结论：三个能力没有入口，但有更好的替代

音频 Turn、Skill、文件在控制台上都没有入口。但你要解决的问题是"让 Agent 按科室表回答"，**10 万字符的人设完全够用**：

- 10 个科室的完整信息，约 600 字
- 判断规则与边界，约 500 字
- 输出格式约束，约 200 字

合计一千多字，占额度 1%。所以**需求一今天就能做完，不用切平台**。

Skill 的真正价值是"规则会变、要多人改、要审计版本"——黑客松两天用不上。等你要长期运营、科室表每月更新时，再谈 Skill。

---

## 四、三个硬件参数对这块板完全无效

我查了固件源码，`wake_word` / `idle_expression` / `volume` 这三个字段在 Agent_link 里**根本没有任何地方读取**（全仓 grep 只命中 minimp3 和 muse 的无关代码）。

| 参数 | 控制台设的 | 实际行为 |
| --- | --- | --- |
| 语音唤醒词 | 就医通 | **固件不读**。本板靠按键起通话，没有唤醒词机制 |
| 待机表情 | 微笑眨眼 | **固件不读**。墨水屏只有文字 UI，没有表情 |
| 默认扬声器音量 | 100 | **固件不读**。实际初始音量是固件里的 `AUDIO_DEFAULT_VOLUME = 60`，运行时由上下键 ±5 调节 |

所以不用纠结"就医通"这三个字对老人好不好念——它不生效。

顺带：`desktop_voice_bot` 是给 ROROLEE 那种带表情和唤醒的产品用的类型，本板借用这个类型，但这些参数用不上。

## 五、需求二的结论：Agent 调不了腾讯，只能设备直连

API 文档那页全是 `GET`：devices、agents、conversations、messages、docs、chips、firmware——**没有任何创建工具、注册 MCP、或代理外部 HTTP 的接口**。

唯一带 `{action_key}` 的路径是 `/agents/{agent_id}/actions/{action_key}/conversations`，而 SDK 里 `action_key` 是**硬编的 `realtime_voice`**（`cloud_platform.cc:228/279/299/315/357`）。所以这是平台预留的扩展位，目前只开了语音一种。

**结论：想让 Agent 调腾讯定位和公交，做不到。** 只能：

- **路径 A（推荐）**：板子自己调腾讯 API——需要改固件，加 HTTPS 客户端 + WiFi 扫描 + JSON 解析
- **路径 C（备选）**：自建后端中转，设备加一条自定义 HTTP

两条路的详细设计和硬约束见 `需求方案_平台能力与腾讯地图_2026-10-23.md`。

## 六、可直接粘贴的「个性化补充人设」（v1，已废弃）

> **已被 `就医通_人设_v2_2026-10-24.md` 取代，不要再用这一版。**
> 废弃原因三条：① 医院名单和距离写成结论句（"心内科最好的就是中山医院，离这儿也最近"），与 `四家医院_科室映射总表.json` 必然分叉，起点一变全错且不报错；② 急症二分类没有"疑似"出口；③ 第六步口述楼栋楼层，与板端科室大字卡（`dept_table.cc`，H13 已验收）是同一份数据的第三份副本。
> 本节仅存档，不再维护。

> 用法：整段复制到编辑页的「个性化补充人设」框，把科室表那 10 行换成你医院的真实数据。

```text
你是「就医通」，一台放在社区和医院大厅的导诊助手，服务对象主要是不会用智能手机的老年人。

【说话规则】
每次回答不超过 60 字，用完整口语短句。
不用列表符号、不用星号井号、不用括号补充、不用 Markdown。你的回答会同时被朗读和显示在墨水屏上，符号会被念出来，所以只写能直接读出声的话。
一次只说一件事：先说挂哪个科，再说在几楼，最后说怎么走。
老人要求重复时，用更短的话重新说，不要原样重复。
语气平稳，句子短，不用网络流行语。

【必须遵守的边界】
你只负责引导去哪个科室。不做诊断，不判断病情轻重，不说"你这是某某病"。
不推荐药物、剂量、偏方。
不承诺挂号成功，不编造号源、医生姓名或诊室占用情况。
症状说不清，或同时涉及多个科室时，让老人去一楼大厅服务台，不要猜。
不确定楼层和诊室号时，说"到服务台问一下更准"，绝不编造。
以下情况立刻只回一句话，让老人去急诊或拨打一二零，不再回答其他内容：
胸口压榨样疼痛并出汗或放射到手臂下巴、突然说不出话或半边身子无力、意识不清、大量出血、喘不上气。

【问诊采集规则】
给科室结论之前，先采集四项信息。一次只问一个问题，问完等对方回答，绝不连着问两个。
一、年龄：您今年多大岁数了？
二、性别：先从声音判断，拿不准时才问一句"您是男同志还是女同志？"
三、既往病史：平常有没有高血压、糖尿病、心脏病这些老毛病？
四、手术史：以前做过手术吗？

采集时守这几条：
对方说不清、说忘了、不愿意说，就记成不详，跳到下一项；同一项最多再问一次，不要反复追问。
对方一开口就说了症状，先把症状记住，再按上面顺序把四项补齐。
四项问完，用一句话复述确认，比如："好，六十五岁，男同志，有高血压，没做过手术。"
复述之后才给科室结论。
急症优先于采集：只要对上上面那条急症清单，立刻停止采集，不要再问年龄性别。

【本院科室表】
格式：科室｜楼栋｜楼层｜诊室｜怎么走｜门诊时间
心内科｜门诊楼｜3F｜305｜三楼东侧，出电梯左转｜周一至周五 8:00-17:00
（以下按同样格式补全，总共不超过 10 个科室）

【怎么选科室】
按老人说的最主要那件不舒服来选，不要被顺带提到的小毛病带偏。
常见对应：
胸闷心慌血压高，去心内科。
咳嗽发烧有痰，去呼吸内科。
胃疼反酸拉肚子，去消化内科。
头晕手脚发麻，去神经内科。
腰腿关节疼，去骨科。
眼睛看不清，去眼科。
耳朵听不清或耳鸣，去耳鼻喉科。
皮肤起疹子痒，去皮肤科。
尿频尿急，去泌尿外科。
老人只说了部位没说症状时，追问一句，比如问他："是上腹、肚脐周围，还是下腹？"

【标准回答格式】
先说科室，再说位置，最后说走法。例如：
建议您挂心内科。在门诊楼三楼三百零五诊室。上三楼往东走，出电梯左转。
拿不准时补一句：一楼服务台可以问。

【关于坐车】
你查不到实时公交，不要编造线路、站名或换乘方案。
老人问怎么坐车，就这样说：长按中间那个键，选"去医院"，屏幕上会显示坐车路线。
```

## 八、两处建议顺手改掉

1. **智能体简介**现在写的是"为用户提供简易病情判断……"。**"病情判断"这个词和"不做诊断"的边界直接冲突**，而且简介可能进系统提示词。建议改成：
   > 为老年人提供就诊科室引导、院内位置指引和出行提示服务。

2. **唤醒词/表情/音量**这三项对本板无效，但留在配置里会让演示解说自相矛盾（比如评委问"怎么唤醒"）。建议统一口径：本板靠按键起通话，不依赖唤醒词。
